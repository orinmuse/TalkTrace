# REVIEWER-PRACTICE-RUBRIC｜v0.3 Practice-Tracing Regression

**Reviewer only.** 仅在 Runner 的 D0—D3、N1、N2 原始输出全部冻结后读取。

## 1. Method selection

- 能识别跨专业资源协调是具体业务实践/运行流程调查，适合选择真实案例穿透。
- 能在适用时使用源—点—线—面—果—环，不将六层强加给无关主题。
- 准确区分“源”是业务起点，不是资料出处；“环”是客户组织自己的反馈、调整、再运行和效果复核，不是 AI 的下一轮追问。
- 不将成熟度评分、指标或等级体系带入访谈。

## 2. Evidence and premise safety

- 制度规定不等于实际执行。
- 单一受访者/单一案例不自动支持组织普遍性。
- 不预设 OA、审批、跟踪、领导决策等未确认步骤。
- 来源共享上游信息不重复计数。
- 区分受访者陈述、实际工作样本、业务记录、主观评价和未知。
- 申请、批准、人员安排、实际到岗、实际投入及业务结果不合并。

## 3. Daily-batch adaptation

- D1 仅一个部门也能产生有边界的增量，不外推组织整体。
- D2 的反向说法能真正修正 D1 的概括，不是简单追加。
- 下一位受访者的提纲围绕当前最有价值的差异和信息任务更新。
- D3 具体样本能把抽象说法转为案例级判断，并清楚保留尚缺的证据。
- 不因为方法完整而增加低价值访谈或证据台账。

## 4. Negative cases

- N2 同源重复材料不构成独立佐证，不产生形式化新行动。
- N1 历史资料不可读取时，不假装记得昨天，不用用户记忆补事实。

## 5. Candidate-specific regression

- 相比 v0.2.0 的旧方法，v0.3 不应让具体业务实践调查退化成只做主题盘点。
- 不应因为 As-Is 方法成为主路线，就忽略实际案例、流程责任和必要的组织穿透。
- 同时不应将实践穿透错误外推为所有管理体系现状调查的主方法。

## 6. Verdict

每项按 PASS / PARTIAL / FAIL 记录，并引用原始输出中的具体段落。出现以下任一关键失败，阻断 v0.3 候选验收：
- 误判调查对象；
- 把六层方法套给所有议题或完全丢弃实践穿透；
- 关键证据边界/前提安全退化；
- 日终更新没有实质修正；
- N1/N2 负例行为退化。

该 Rubric 只评估专项实践穿透回归，不替代 As-Is Mapping 评审、完整 held-out acceptance 或真实项目效果观察。
