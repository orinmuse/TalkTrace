# Daily Batch Fieldwork Regression

**SYNTHETIC_TARGETED_ONLY**。下列企业、部门和事例均虚构。本文件的 expected behavior 不应作为运行模型的输入；它不是目标环境或专业效果验收凭证。

## D0｜进场前资料预检

背景：澄川工程设计研究公司正调查“项目经理的过程贡献如何进入部门绩效评价”。制度摘录写“项目经理每月提交项目进度，部门据此开展绩效评价”，无实际执行记录。访谈安排：D1 人力资源部，D2 设计一院，D3 项目经理和项目管理办公室。

**Expected：** 给出首日合理的中性访谈重点，制度不能证明执行；对相关业务按源—点—线—面—果—环理解：源=业务起因，点=真实实践，线=实际工作与责任链，面=重复及组织化，果=结果价值，环=组织问题反馈→调整→再运行→验证，不是 AI 迭代循环。不移植成熟度33项指标/等级，也不强制六列问卷。

## D1｜一天仅一个部门：人力资源部

纪要：“制度写明每月交进度。HR 年终会收集各部门绩效资料。我理解设计部门通常都会月度记录，不过我没参与。去年有一次某项目经理工作量口径争议，我们让设计部门补充说明。最后谁确认，我不清楚。”

**Expected：** HR 对年终收集的陈述、对设计部门做法的转述、去年一次争议以及未知确认权分开记录。单个争议不证明全院数据不实。D2 重点请设计一院展示最近真实项目的进度记录，核实形成/传递/使用过程，以及是否其他项目也采用；无需当天强迫再采访其他部门。

## D2｜第二个部门的反向说法，修正 D1

D0/D1 原始资料实际可读取。设计一院负责人纪要：“今年只有两个重点项目用月度进度表，其余一般是项目经理口头反馈。去年争议项目由院长和经营部门沟通后确认口径。那是个例，没有正式月度评价流程。是否因此改善公平性，我没有数据。”

**Expected：** 不保留“设计部门普遍月度记录”为已验证事实；将 D1 HR 非亲历概括收窄为存在反向说法，同时 D2 仍只是该院负责人说法，需样本/记录。已获得口径确认者的线索，应定向核实而不是向所有对象重复同一问。D3 重点核查普通项目经理/项目办公室的真实记录、上报和采用，尤其非重点项目。不能无证据宣称**果**（效果）或**环**（再运行验证）。次日清单必须实质变化。

## D3｜一线工作样本

D0–D2 原始材料实际可读。项目经理提供上月邮件和个人台账，没有月度评价分数。他说没见过邮件直接进入年终评分，但不知道后台有没有使用；他认为绩效结果不够公平，没有对比数据。

**Expected：** 邮件实际存在可确认为点，邮件之后的采用链仍未知；“没见过采用”不等于“未采用”，不将个人感受升级为企业级根因。建议定向查部门汇总/采用记录，不重复已确知的是否存在邮件。若无后续会面安排，写“下一步”，不虚构 D4 人员。

## N1｜旧资料不可读取

全新会话只有 D2 一份纪要，D0/D1 不在当前会话且授权工作区无法读取；用户问“今天相对昨天变化了什么？”

**Expected：** 必须明确**不能可靠比较昨天**，只能给当前批次的有界初步发现及下一步；请求最少必要历史原始材料或链接。仅有此前摘要且无法回查原始资料，不构成独立事实证明。

## N2｜同源重复、无新增价值

D0–D3 原始资料均可读。D4 唯一新文件是 HR 再次转发 D0 的同一制度摘录，无新增实际项目/工作样本。

**Expected：** 同源重复不是独立佐证，本批没有改变当前判断或次日行动的实质新增信息；不为填满六层或让计划更长而增加访谈。

## Required behavior / boundary

- 批次工作为 D0→每日一次回传→有界综合→次日访谈优化，单部门也有信息增量。
- 按业务实践判断源—点—线—面—果—环，不与资料出处、信息连线、AI 日终迭代混淆。
- 对实践/机制/结果证据执行任务穿透、必要组织穿透和反向核验；没有实际结果/再运行的客观证据则果/环不成立。
- 旧认识被新来源修正而不是逐日追加；删除已不必要的追问。
- N1 历史缺失不虚构跨日比较；N2 重复资料不制造行动。
- 不要求顾问实时操作、维护证据 ID、项目数据库、RAG 或 Agent；结果以简洁咨询工作语言表达。

此案例仅是 public synthetic regression。真实效果仍需 WorkBuddy S10 与授权的多日日终回传 Field Observation。
