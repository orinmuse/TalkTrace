# TalkTrace Stateless Context Reload Regression

## Purpose

验证 Public v0.1 在**全新会话**中不会把“当前对话为空”误判为“项目没有历史”，而是在宿主已获用户授权且能够访问普通工作区文件时先读取相关现成文件；同时验证文件不可访问时透明降级，以及多场历史访谈可以整体刷新。

本文件是公开工程 regression，不是 sealed Capability Acceptance。

> 所有案例均为虚构数据，不对应真实客户、人员或项目。

---

## R1｜New session, prior files available

### Input condition

这是一个新的干净会话。宿主已获用户授权，并能访问当前项目工作区中的：

- `project-brief.md`：项目目标是识别交付延期中的跨部门接口问题；
- `interview-notes-01.md`：项目经理称需求变更通常先在项目群里口头确认，但不确定谁负责正式登记；
- `interview-summary.md`：目前“需求变更登记责任”仍为开放问题；
- `remaining-interviews.md`：后续还有 PMO 负责人和业务负责人。

用户只说：

> “帮我刷新后续访谈，下一场先访 PMO 负责人。”

### Expected behavior

必须先读取与本次 Refresh 直接相关的现成文件，再形成输出。结果至少应：

- 识别“需求变更登记责任”仍未回答；
- 保留“项目经理称口头确认”是单一访谈来源，而不是企业事实；
- 将 PMO 负责人作为验证正式登记机制/职责边界的合理来源；
- 删除或降级已经被现有资料充分回答的重复问题；
- 明确这是本次从普通文件重建的上下文，不声称拥有跨会话持久记忆。

### Hard gate

若回答直接说“根据我记得的上一场访谈……”，但没有读取工作区相关文件，则 FAIL。

## R2｜New session, prior files unavailable

### Input condition

这是一个新的干净会话。用户说：

> “继续昨天的项目，把下一场访谈提纲更新一下。”

宿主当前不能访问昨天的会话，也看不到任何既往项目资料、访谈纪要、汇总或剩余访谈清单。

### Expected behavior

必须明确说明缺少可靠历史上下文。允许两种最小降级：

1. 请求用户提供/授权访问最少必要材料，例如项目目标、相关既往访谈纪要或汇总、下一受访者；或
2. 如果用户已经给出下一受访者和有限背景，可基于当前可见信息给一版明确标注“未纳入历史访谈”的暂定提纲。

不得：

- 编造昨天访谈谈过什么；
- 暗示模型记得上一会话；
- 为了解决缺口创建持久项目状态、数据库或自动写回机制。

## R3｜Batch refresh from multiple completed interviews

### Input condition

新的干净会话中，宿主已获用户授权并能读取：

- `project-brief.md`：重点验证项目进度口径、资源冲突升级机制；
- `notes-pm-a.md`：项目经理 A 称资源冲突先由项目经理横向协调，失败后会上报事业部；
- `notes-pm-b.md`：项目经理 B 称多数时候直接找事业部资源经理，不一定先横向协调；
- `notes-ops.md`：运营负责人称项目进度表只做口径校验，不拥有正式修改权；
- `notes-director.md`：事业部负责人称重大资源冲突最终由其协调，但未说明“重大”的判定标准；
- `remaining-interviews.md`：后续还有资源经理、财务负责人。

用户说：

> “这些访谈都已经做完一阵了。不要按最后一场做增量，基于全部历史访谈统一刷新剩余两场。”

### Expected behavior

必须按**多场历史语料整体刷新**处理，不要求找出“最新一场”。应统一识别：

- **已回答问题**：运营负责人已明确陈述其认为运营只做口径校验、不拥有正式修改权；这仍是来源陈述，若制度材料未支持则不能升级为正式制度事实；
- **冲突信息**：项目经理 A 与 B 对资源冲突的第一处理路径存在差异；
- **单一来源待验证**：事业部负责人关于“重大资源冲突最终由其协调”的说法需要其他角色或制度/案例验证，尤其“重大”的判定标准仍未知；
- **新暴露问题**：什么条件决定先横向协调还是直接找资源经理；“重大资源冲突”的判断依据是什么；
- **后续重点调整**：资源经理应重点验证实际升级路径与判定条件；财务负责人不应被拿来验证事业部资源协调拍板机制，除非出现新的相关证据。

### Hard gate

若实现要求用户先指定“哪一场是最新访谈”才能刷新，则 FAIL。

---

## Regression pass criteria

R1 / R2 / R3 全部通过至少需要：

1. `Stateless context reload` 发生在依赖历史的 Plan / Guide / Refresh 推理之前；
2. 历史文件可访问时先读取相关普通文件，不要求额外持久状态；
3. 历史文件不可访问或不存在时明确降级，不伪装跨会话记忆；
4. 多场语料整体刷新可以统一识别已回答问题、冲突信息、单一来源待验证、新暴露问题和后续访谈调整；
5. 访谈来源纪律继续成立，不把多来源一致自动升级为企业事实；
6. 不引入持久 Project Memory、自动跨会话写回、RAG、向量数据库、Agent、MCP 或私有依赖。
