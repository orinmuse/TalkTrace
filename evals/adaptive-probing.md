# Adaptive Probing & Evidence-Fit Regression

## Purpose

验证 TalkTrace 是否能根据实际回答选择下一步追问，并判断证据能支持什么范围。该文件是公开 synthetic regression，不是 sealed Capability Acceptance evidence，也不能证明真实项目价值。

## Synthetic case｜澄川工程咨询公司

以下公司、项目、角色和记录均为虚构。

项目组正在了解项目月度经营数据如何进入部门管理。当前材料只说明：

- 项目经理每月提交项目进度和预计完成情况；
- 运营中心汇总形成月度项目表；
- 现有材料没有说明运营中心是否审核、修改、反馈或追踪项目数据；
- 没有材料说明上述做法是否为稳定机制。

拟访谈运营中心一名业务经理，目标是了解月度数据从提交到进入管理使用的实际过程。

## Stage 1｜Initial guide

**Prompt**

> 给运营中心业务经理准备一份30分钟的顾问内部访谈提纲，重点了解项目月度数据的实际处理过程。

**Expected behavior**

- 先用开放问题还原实际过程，不预设存在审核、修改、反馈或追踪；
- 内部版标明本题要确认的主张和适用范围；
- 可选追问是条件式的，不把所有维度塞进一个长问题；
- 预留现场追问时间。

## Stage 2｜Generic answer

**Interviewer asks**

> 项目经理提交月度进度后，运营中心实际会怎么处理？

**Respondent answer**

> 我们一般都会看一下，发现不太合理的就会调整，最后形成月报。

**Required adaptive next move**

TalkTrace 应识别这仍是概括性陈述，且“调整”行为、主体、依据和权限尚未明确。优先追问一个最近的具体案例，例如：

> 能否举最近一次实际发生的例子，讲讲当时具体发生了什么？

不得直接问“你们通常由谁审核、按什么权限调整”，因为审核职责和正式权限尚未确认。

## Stage 3｜Branch by answer

### Branch A｜First-hand case

**Respondent**

> 上个月有一个项目把预计完成比例从80%改成了65%，是我们这边的同事提出的，项目经理后来补充了说明。

**Required behavior**

- 将该事件记录为一个具体案例，不自动升级为稳定机制；
- 只选择当前最缺且影响判断的一个维度继续追问；如仍需其他信息，分步追问，不把调整依据、参与者、记录和最终结果合并成一串复合问题；
- 如需判断普遍性，再单独询问其他月份/项目是否也有类似情况；
- 不预设提出调整的人拥有正式审核权。

### Branch B｜Second-hand account

**Respondent**

> 具体我没经手，是听同事说有时会调整。

**Required behavior**

- 将其标记为转述，不作为独立佐证；
- 询问最可能的直接经办人或可回查的记录；
- 不继续追问受访者猜测调整流程。

### Branch C｜No knowledge

**Respondent**

> 我不负责这部分，不清楚。

**Required behavior**

- 不将“不清楚”解释为没有相关处理；
- 停止对该受访者追问机制细节；
- 建议转向实际经办人、流程 owner 或相关业务记录。

### Branch D｜Formal document supplied

**Respondent**

> 制度规定运营中心要审核项目月报。

**Required behavior**

- 制度可以支持正式职责/规则存在；
- 继续区分制度规定与实际执行，必要时用一个真实案例验证；
- 不因制度条文直接认定每次都按制度执行。

## Stage 4｜Evidence-fit, scope and independence

**Required checks**

1. 对 Branch A，证据基础为亲历案例，适用范围为单一项目/月份；验证状态只能支持该案例，频率主张仍待验证。
2. 制度文件支持正式规定，不单独证明实际执行。
3. 转述不等于亲历，也不自动构成独立佐证。
4. 多人说法若来自同一会议/上级/文件，不得重复计数为独立来源。
5. 频率主张需要适当的跨案例、连续记录或其他覆盖证据。
6. 权限主张需要适当的正式授权依据和/或实际决策记录。
7. 没有证据或受访者不掌握信息，不等于事项不存在。
8. 对 Branch D，证据基础为正式制度文件，适用范围是制度规定对象；制度设计可以得到支持，但实际执行仍待验证。
9. 分开记录证据基础（文件/数据/亲历/转述/观点）、适用范围（案例/团队/组织/时间）和验证状态（待验证/得到支持/独立佐证/冲突/未解决/满足当前用途），不得合并为一个证据等级。
10. 来源独立性之外，还应考虑来源是否直接接触事件、职责观察范围和是否共享上游信息；不得据此推断受访者动机。

## Pass criteria

- 下一问随回答变化，而不是每次重复同一固定追问清单；
- 每轮优先问一个最有价值的问题，不把全部追问堆成复合问句；
- 概括性说法优先落到具体案例；
- 亲历、转述、观点、制度和数据不混淆；
- 证据与主张类型、范围和时间匹配；
- 证据基础、适用范围和验证状态分别表达，不混为一个标签；
- 单一案例不被泛化；
- 来源独立性得到检查；
- 不能回答时正确转交下一来源，而不是继续逼问；
- 内部机制不泄漏为用户必须学习的新操作术语；
- 不建立持久状态、数据库、证据图谱或数值评分。
