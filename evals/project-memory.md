# TalkTrace Local Project Memory Regression

## Purpose

验证 TalkTrace 能否使用项目本地 Markdown，在没有旧聊天记录的全新会话中恢复项目语境和项目状态，并在新增材料/访谈后进行可追溯的增量更新。

本案例应使用完全合成的项目资料。真实客户项目、人员、数据、访谈和项目记忆不得进入仓库或测试包。

## Test environment precondition

运行环境必须提供一个测试项目目录，并允许：

- 读取目录中的合成 Word/PDF/Excel/Markdown 等材料；
- 创建和更新 `talktrace/` 下的 Markdown 文件；
- 结束会话后，在全新会话中重新打开同一目录。

如果运行环境不支持持续访问同一项目目录，应记录为 **persistent local-folder runtime blocker**，不得用同一聊天上下文代替本测试。

## P1｜Initialize

在没有 `talktrace/` 目录的合成项目中执行：

> 根据当前项目资料建立项目记忆，并告诉我目前项目处于什么阶段、已经知道什么、还缺什么。

通过条件：

1. 创建 `talktrace/project-memory.md` 和 `talktrace/source-register.md`；
2. 原始材料没有被修改、移动、覆盖或删除；
3. 项目记忆包含项目背景、语境、信息状态、项目状态和下一步；
4. 来源登记能够回指原始文件；
5. 对无法完整读取的版式、图表或复杂表格明确保留限制；
6. 用户没有被要求手工填写 Schema 或来源编号。

## P2｜Clean-session recovery

关闭上一会话，在不提供旧聊天记录的全新会话中重新打开同一项目目录，然后执行：

> 继续这个项目。现在最需要推进什么？下一场访谈应该重点解决哪些问题？

通过条件：

1. 首先加载已有 `project-memory.md` 和 `source-register.md`；
2. 能恢复项目目标、当前阶段、已完成工作、核心缺口和下一步；
3. 不声称记得上一轮聊天；
4. 输出依据来自项目记忆及可访问来源，而不是重新发明项目背景；
5. 不要求用户重新上传已经存在于项目目录中的可访问材料。

## P3｜Incremental interview update

向项目目录加入一份新的合成访谈记录，然后执行：

> 整理这场访谈，更新项目记忆，并据此调整后续访谈重点。

通过条件：

1. 新访谈被登记为独立来源；
2. 新增信息、已回答问题、冲突和新问题被正确识别；
3. 受访者陈述没有升级为材料明确或企业事实；
4. 不受影响的既有记忆被保留；
5. 冲突来源并列保留，没有静默覆盖；
6. 项目状态、后续访谈重点和最近更新时间被增量更新；
7. 重要更新在 `history/` 留下简短 Delta。

## P4｜Changed source

更新一份已登记合成材料的内容或修改时间，然后重新运行。

通过条件：

1. 运行环境可提供文件变化信息时，TalkTrace 能发现变化并复核受影响内容；
2. 无法获得变化信息时，TalkTrace 不虚构已完成检测；
3. 新版本与旧记忆冲突时，先标记变化和待复核，不静默覆盖；
4. 来源登记保留版本或变化说明。

## P5｜Failure and recovery

分别测试：

- 项目目录只读；
- `project-memory.md` 缺失；
- YAML/frontmatter 或关键结构损坏；
- 打开另一个项目但误用旧项目记忆；
- 原始来源暂时不可访问。

通过条件：

1. 不破坏现有文件；
2. 不在写入失败后声称已保存；
3. 项目身份不一致时停止写入；
4. 能恢复时优先使用来源登记、历史记录和原始材料；
5. 不能恢复时明确说明缺口及需要用户完成的最小动作。

## Hard gates

- 不能依赖旧聊天才能恢复项目；
- 不能修改或删除原始项目材料；
- 不能把 Markdown 描述为所有原文件信息的无损复制；
- 不能把访谈陈述或模型推断静默升级为已验证事实；
- 不能静默覆盖冲突或用户无法识别用途的自定义内容；
- 不能在文件写入失败后声称项目记忆已更新；
- 不能把真实客户数据写入公开仓库。

## Acceptance note

本文件是公开工程回归用例，不能单独承担最终 Capability Acceptance。发布前仍需使用未向实现者暴露的合成 holdout 项目，验证跨会话恢复、增量更新、来源纪律、失败恢复和相对 no-Skill baseline 的实际价值。
