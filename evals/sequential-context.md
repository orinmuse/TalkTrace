# TalkTrace Sequential Context Regression Case

## Purpose

验证 TalkTrace 的新版核心价值：**前一场访谈进入当前上下文以后，后一场访谈应因为新增信息而实质改善。**

本案例是公开合成 regression case，不作为最终 Capability Acceptance 的唯一 held-out evidence。最终发布前仍需 Skill Manager 预注册独立 sealed held-out cases。

---

# Synthetic Case｜海岚城市技术咨询有限公司

> 本案例完全虚构，仅用于公开测试，不对应任何真实客户、企业、人员、制度或项目。

## 项目背景

海岚城市技术咨询有限公司约 420 人，设三个区域事业部和一个运营管理中心，主营城市更新咨询、工程设计与项目管理。

公司正在开展一次“项目履约与资源协同”专项调研，希望了解：

1. 项目进度信息如何进入经营管理；
2. 区域事业部内部资源冲突如何协调；
3. 项目经理、事业部负责人和运营管理中心在履约管理中的实际分工；
4. 管理口径与财务收入确认口径之间如何衔接，但本轮不直接判断财务制度是否合理。

## 已知材料事实

1. 《项目月度管理办法》规定：项目经理每月提交进度与预计完成情况，运营管理中心汇总形成公司月度项目表。
2. 财务收入确认依据合同、验收和财务制度执行，材料没有说明财务确认口径与运营月度进度口径完全一致。
3. 区域事业部负责人负责本事业部经营目标和人员统筹。
4. 当前材料没有说明：
   - 运营管理中心是否有权修改项目经理提交的进度数据；
   - 区域事业部负责人在项目资源冲突中具体如何介入；
   - 不同项目之间临时调配人员的实际决策步骤。

## 已知角色

- **副总经理 叶航**：分管运营与区域事业部协同；
- **运营管理中心主任 唐霖**：负责项目月报、履约跟踪与运营分析；
- **东区事业部总经理 吴川**：负责东区经营和人员统筹；
- **项目经理 陈柏**：负责东区一个城市更新设计项目；
- **财务经理 苏宁**：负责收入确认和经营分析。

# Stage 1｜Before the first interview

## Prompt A

> 根据这些项目资料，给项目经理陈柏准备一份 35 分钟的顾问内部访谈提纲。

## Expected behavior

提纲应重点了解项目一线实际运行，而不是假装已经知道真实流程。

应包括但不限于：

- 项目经理实际如何形成并提交月度进度信息；
- 项目出现资源冲突时实际怎么处理；
- 最近一次真实资源协调案例；
- 项目经理看到的运营管理中心、事业部负责人实际参与方式；
- 管理进度与财务确认在项目经理视角下是否存在口径差异。

### Hard gate

不得直接问：

> “运营管理中心为什么会修改你提交的进度数据？”

因为材料没有证明运营管理中心会修改。

也不得直接问：

> “吴总通常在什么情况下会调人解决资源冲突？”

因为材料只说明事业部负责人有人员统筹职责，没有证明具体介入步骤。

# Stage 2｜New interview enters the current context

## New transcript｜项目经理陈柏

> “月度进度是我们项目经理自己填，填完交运营中心。一般他们会回来问一些依据，比如设计阶段完成比例为什么这么填。有时候他们会让我们改，但我不清楚这是他们正式审核权限还是只是觉得口径不一致。上个月我们项目缺两个结构工程师，我先找另外两个项目经理协调，没有协调下来，后来在事业部周会上提了这个事，最后从另一个项目临时借了两个人三周。到底是谁最后拍板我不敢说，我理解是吴总协调的，但这个要问他。财务确认跟我们填的月度进度不是一回事，财务还是看合同和验收。我们项目团队更关心内部管理进度。”

---

# Stage 3｜Interview Delta

## Prompt B

> 结合前面的项目资料和刚才陈柏的访谈，告诉我这场访谈新增了什么、哪些需要继续验证，以及后面的访谈应该怎么调整。

## Must identify

### 新增信息

至少识别：

- 陈柏称运营管理中心会对项目经理填写的进度依据进行询问，并“有时候让项目经理改”；
- 陈柏不清楚这属于正式审核权限还是口径协调；
- 陈柏提供了一个资源冲突案例：先由项目经理之间协调，未解决后在事业部周会上提出，最终从另一项目临时借两名结构工程师三周；
- 陈柏认为吴川进行了协调，但明确说“到底是谁最后拍板不敢说，需要问吴川”；
- 陈柏明确区分内部管理进度与财务收入确认口径。

### Source discipline

必须保持：

- “运营中心有时让项目经理改”是陈柏的访谈陈述，不得直接写成正式制度事实；
- “吴总协调/拍板”存在不确定性，不能升级成确定事实；
- 财务确认依据合同和验收在正式材料已有支持，而陈柏的表述只是进一步说明其项目端理解。

### Questions answered / partially answered

至少识别：

- 资源冲突不是纯抽象问题，已经获得一个具体案例；
- 项目经理之间会先尝试横向协调这一点得到单一来源支持；
- 运营中心对项目进度数据存在某种反馈/校正行为得到单一来源支持，但权限性质未解决。

### New/open questions

至少包括：

- 运营管理中心对月度项目进度究竟是形式汇总、口径校正、审核还是有其他正式职责；
- 资源冲突升级到事业部层面后实际由谁决定、依据是什么；
- 临时借调人员是否有固定规则还是案例性协调。

### Best next sources

- 运营管理中心主任唐霖：验证进度数据反馈/修改的实际机制和权限来源；
- 东区事业部总经理吴川：验证资源冲突升级后的实际决策流程；
- 不应把财务经理作为验证“吴川是否拍板”的首选对象。

# Stage 4｜Refresh the next interview

## Prompt C

> 现在给东区事业部总经理吴川准备一份 40 分钟的顾问内部访谈提纲。要利用刚才陈柏访谈得到的信息，不要重复已经知道的内容。

## Expected material improvement

相比 Stage 1 之前的一般性吴川提纲，更新版必须体现真实信息增量。

### Should remove / downgrade

不应继续把大量时间用于泛泛询问：

- “项目遇到资源冲突时会不会协调？”

因为已经有一个具体单一来源案例，更高价值的任务是验证真实升级与决策机制。

### Should add / sharpen

应中性验证：

1. **资源协调案例的实际流程**
   - 可以引用“项目经理陈柏提到上月一个项目发生临时借调两名结构工程师三周的案例”，但必须标明这是受访者陈述；
   - 询问吴川如何理解这个案例实际经历的步骤、分别有哪些角色参与；
   - 不得预设“吴川最终拍板”。

2. **事业部负责人介入边界**
   - 什么类型的资源问题由项目经理之间解决；
   - 什么情况下才会上升到事业部层面；
   - 如果进入事业部层面，实际如何形成决定。

3. **与运营管理的接口**
   - 吴川如何使用月度项目进度信息进行事业部管理；
   - 如果项目经理与运营中心对进度口径理解不同，事业部负责人通常看到什么、如何处理；
   - 不得把“运营中心有正式修改权”作为事实前提。

### Should route elsewhere

关于“运营管理中心正式有什么审核/修改权限”的制度性细节，应记录为更适合向唐霖验证，不应为了显得全面把所有问题塞给吴川。

---

# Pass criteria

本 sequential regression 通过至少需要：

1. Stage 3 真正识别“新增/已回答/冲突或不确定/新问题”，而不是重写一遍纪要；
2. 单一来源陈述不被升级为企业事实；
3. 能把不同未知问题分配给更合适的后续角色；
4. Stage 4 相比无前序访谈时明显减少重复，并利用新案例形成更高价值验证；
5. Stage 4 不预设吴川拍板，也不预设运营中心具有正式修改权；
6. 不要求建立项目状态文件、数据库、RAG 或额外用户维护动作；
7. 若前序资料不在当前上下文，应透明说明无法可靠完成增量刷新。
