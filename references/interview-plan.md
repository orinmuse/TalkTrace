# Interview Plan Workflow

## Purpose

把本地项目记忆和当前可访问的项目资料转化为：

> **项目要回答什么 → 还缺什么信息 → 谁最适合提供/验证 → 应访谈谁 → 建议多长时间 → 如何形成可执行计划。**

排时间是最后一步，不是访谈设计的起点。

## 1. Build a lightweight interview context

先按 `references/project-memory.md` 加载 `talktrace/project-memory.md` 和来源登记，再只提取与本轮访谈设计直接相关的信息：

- 项目目标 / 本轮调研真正需要回答的问题；
- 正式组织、岗位、领导分工与职责；
- 已经由材料明确的信息；
- 当前仍未知或需要验证的信息；
- 已有访谈中出现的重要说法、冲突和待验证点（如果存在于项目记忆或当前材料）；
- 已知人员名单；
- 已知访谈时段、分组和固定安排。

不要为了形式重新生成完整项目档案，也不要把“材料没有说明”改写成“实际不存在”。计划形成或调整后，将访谈对象、信息任务、排程状态和关键缺口增量写回项目记忆。

## 2. Build the information-need map first

在选人之前，先内部回答：

1. 这个项目当前最重要的未决问题是什么；
2. 每个问题需要什么类型的信息才能被推进；
3. 哪些信息已经由材料回答，不值得重复访谈；
4. 哪些重要说法只有单一来源，需要第二来源验证；
5. 哪些问题需要不同角色提供互补视角。

不要求把这张内部信息图完整展示给用户；它服务于后续对象选择。

## 3. Recommend interviewees by information value

对候选对象使用可解释逻辑：

`待解决问题 × 信息掌握可能性 × 决策/执行角色 × 视角独特性 × 交叉验证价值`

默认分类可使用：

- **主要领导 / 核心决策者**：目标、原则、重大取舍、边界和最终决策；
- **核心干系人**：关键制度、机制、流程或实施 owner；
- **普通干系人**：重要运行信息和执行体验；
- **补充/验证对象**：补足一线、例外、专业视角或第二来源。

对每个建议对象至少保留：

- 为什么需要访谈；
- 最希望获得/验证什么；
- 与哪个项目问题相关；
- 是否承担交叉验证角色。

### 不得做

- 仅按职位高低机械排序；
- 根据正式头衔推断真实政治影响力；
- 为了显得全面而机械覆盖所有部门；
- 编造人员姓名、职责、可用时间；
- 把“可能掌握某信息”写成“确定掌握”。

## 4. Decide priority and duration

访谈时长由信息价值、问题复杂度和角色决定；以下仅作为可覆盖默认值：

| 对象类别 | 默认建议时长 |
|---|---:|
| 主要领导 / 核心决策者 | 60 分钟 |
| 核心干系人 | 45 分钟 |
| 普通干系人 | 30 分钟 |
| 补充 / 验证对象 | 15 分钟 |
| 场间休息 | 10 分钟 |

用户明确要求、项目现实或既定客户安排优先。

同一类别的人不必使用同样时长。如果某对象承担多个关键未决问题或重要交叉验证，可适当增加；如果只是补足单一信息，可缩短。

## 5. Ask only material scheduling questions

只有用户要求正式排程，且以下信息缺失并会改变结果时才询问：

1. 几天完成 / 每天可用时段；
2. 有几个访谈组，是否并行；
3. 是否已有固定时间；
4. 是否要调整默认时长。

已有答案不得重复询问。

## 6. Scheduling logic

排程同时考虑执行约束与信息价值：

1. 用户/客户已固定时间；
2. 每日可用窗口和访谈组数量；
3. 必要休息/整理缓冲；
4. 能显著提高后续访谈质量时，可优先安排能够解释整体机制或关键争议的对象；
5. 如果顺序没有明确业务价值，不制造复杂“最优排序”。

不要伪造访谈对象的实际可用时间。

## 7. Output

默认输出结构化表格：

| 日期/天次 | 时间 | 时长 | 访谈对象 | 职务/部门 | 对象类别 | 主要访谈目的 | 重点验证/信息缺口 | 访谈组别 | 备注 |
|---|---|---:|---|---|---|---|---|---|---|

需要固定字段时可使用 `assets/interview-plan-template.csv`。

用户明确要求可下载、可编辑 Excel 且宿主运行环境支持时，应生成真实电子表格文件；如果环境不能生成，应如实说明，不能用 Markdown 表格冒充。

表格之后只保留真正需要顾问确认的事项，例如：

- 可能遗漏的关键对象；
- 角色/信息掌握判断仍不确定；
- 固定时间冲突；
- 因资料不足采用的重要假设。

## 8. Quality check

完成前检查：

- 是否从“信息缺口”而不是“职位名单”出发；
- 每个关键未决问题是否有合理的信息来源/访谈角色；
- 重要单一来源说法是否安排了必要的交叉验证；
- 是否存在重复、低信息价值访谈；
- 对象分类和访谈目的是否有当前资料依据；
- 时长、顺序和日程是否可执行；
- 是否违反用户已给定约束；
- 是否把建议写成未经确认的组织事实。
