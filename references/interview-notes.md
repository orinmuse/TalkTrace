# Interview Notes Workflow

## Purpose

把访谈转写或记录整理成可继续分析和核实的结构化纪要，同时保留受访者原意、重要限定和证据边界。

TalkTrace 整理的是“访谈来源信息”，不是自动判定企业事实。

## 1. Accepted input

优先使用当前环境可直接读取的：

- 访谈转写文本；
- Markdown / TXT；
- Word-like readable text；
- 现场记录与转写组合材料。

原始音频转写不是 v0.1 必需能力。若当前运行环境能可靠转写，可把转写结果作为输入；否则要求提供可读文本。

## 2. Preserve the source before summarizing

先识别受访者实际表达的：

- 核心观点；
- 事实性陈述；
- 具体案例；
- 判断/评价；
- 建议；
- 数字、时间、范围和例外；
- 明确“不知道 / 不确定 / 需要确认”的内容。

不得因为结构化输出而丢掉会改变意思的重要限定。

## 3. Default structure

```markdown
# 访谈纪要

## 1. 基本信息
- 受访者：
- 职务/角色：
- 时间：
- 主题：

## 2. 核心观点

## 3. 关键事实性陈述

## 4. 典型案例与例证

## 5. 问题与建议

## 6. 待核实事项
```

如果输入材料没有基本信息，不要自行补造。

## 4. Meaning of “factual statement”

“事实性陈述”仅表示：

> 受访者把该内容当作事实、流程、事件或数字进行描述。

它不表示该内容已经被其他资料、数据或独立来源验证。

必要时使用类似表述：

- `受访者称……`
- `据受访者介绍……`
- `该说法尚需结合制度/数据核实。`

不要把这些来源限定在压缩纪要时删除。

## 5. Distinguish statement types when material

当区分会影响后续判断时，至少识别：

- **事实性陈述**：对流程、事件、数据、角色行为的描述；
- **观点/判断**：受访者对原因、效果、优先级等的解释；
- **建议**：希望未来如何调整；
- **案例**：用于说明观点或事实的具体例子；
- **待核实项**：无法仅凭本次访谈确认的关键内容。

不需要给每一句话强制打标签；只在有助于后续使用时结构化。

## 6. Uncertainty and transcript defects

出现以下情况时不得自行补全：

- 转写明显缺字或中断；
- 人名、数字、制度名称听写不清；
- 指代对象无法确定；
- 前后说法互相矛盾；
- 记录只保留片段，无法确认完整语境。

使用 `待核实`、`原记录不清`、`无法确认` 等明确标记。

## 7. Optional project-context comparison

如果当前上下文已经存在项目资料，且存在清晰、重要的关系，可以补充：

- 与正式资料一致；
- 补充了资料未说明的运行信息；
- 与已有资料存在冲突；
- 尚不能判断。

这只是信息导航，不是诊断结论。

不要为了显得专业，强行给所有观点做“证据关系”分类。

## 8. Follow-up suggestions

只有出现明确的信息缺口或矛盾时，才增加后续建议，例如：

- 查哪一份制度/数据；
- 向哪类角色继续确认；
- 下一场访谈应追问什么。

不要自动生成大段行动计划。

## 9. Quality check

完成前检查：

- 有没有遗漏会改变理解的重要观点、数字或案例；
- 有没有把受访者观点写成客观事实；
- 有没有增加原文不存在的原因、动机或评价；
- 重要限定词是否被压缩掉；
- 不确定内容是否被明确标记；
- 纪要是否足够简洁，能够被后续顾问直接继续使用；
- 是否越界形成了企业级正式诊断。
