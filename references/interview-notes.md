# Interview Notes Workflow

## Purpose

把访谈转写或记录整理成**顾问可直接继续使用的轻量纪要**，同时保留受访者原意、重要限定和来源边界。

TalkTrace 整理的是访谈来源信息，不自动判定企业事实。来源纪律属于内部推理约束，除非对理解有实际影响，不应把纪要写成证据审计报告。

## 1. Accepted input

优先使用当前环境可直接读取的：

- 访谈转写文本；
- Markdown / TXT；
- Word-like readable text；
- 现场记录与转写组合材料。

原始音频转写不是 v0.1 必需能力。若宿主运行环境能可靠转写，可把转写结果作为输入；否则要求提供可读文本。

## 2. Preserve the source before summarizing

先识别受访者实际表达的，并在内部区分原始来源与从来源提取的信息点：

- 核心观点；
- 关键事实与流程陈述；
- 具体案例；
- 判断/评价；
- 建议；
- 数字、时间、范围和例外；
- 明确“不知道 / 不确定 / 需要确认”的内容。

对会影响判断的重要信息，保留来源锚点，并区分“受访者这样说”“原始记录显示”和“顾问据此推断”。一个来源可以包含多个信息点；多个来源也可能支持同一信息点。不得因为结构化输出而丢掉会改变意思的重要限定，也不必把每句话拆成独立信息点。

## 3. Default user-facing structure

默认优先使用以下轻量结构：

```markdown
# 访谈纪要

## 核心观点

## 关键事实与案例

## 待核实事项

## 对后续访谈的影响
```

规则：

- “基本信息”只有在输入明确提供且对后续工作有用时再保留；
- “问题与建议”只有受访者确实提出时再单列；
- “对后续访谈的影响”只写真正会改变后续验证对象或问题的事项，没有则省略；
- 不为了展示方法而机械增加“事实性陈述 / 竞争性解释 / 单一来源 / 已验证事实”等标签；
- 当来源边界会改变理解时，用自然语言简短保留，例如“江屿认为……”“该案例仍需向人力核实”。

需要稳定版式时，可使用 `assets/interview-notes-template.md`。没有来源支持的字段直接删除，不得为了填满模板补造信息。

## 4. Internal source discipline

模型内部仍需区分：

- 对流程、事件、数字的来源陈述；
- 观点/判断；
- 建议；
- 案例；
- 待核实事项。

但这些分类默认不应全部显式展示给用户。

任何受访者陈述都不自动等于已被其他资料、数据或独立来源验证的企业事实。必要时才使用：

- `受访者称……`
- `据受访者介绍……`
- `该说法仍需结合制度/数据/其他访谈核实。`

不要在压缩纪要时删除会改变结论强度的来源限定。

## 5. Preserve source trace when available

如果原转写/记录已经包含时间戳、段落号、说话人标签、页码或其他稳定定位信息：

- 对重要数字、关键流程、典型案例、争议性表述和待核实事项，优先保留简短来源定位；
- 定位应足以帮助顾问回查，不要求给每一句话建立引用；
- 输入没有定位时，不生成虚假时间戳、段落号或页码；
- 不为了“可追溯”建设额外证据图谱、数据库或复杂编码体系。

### Claim scope and source basis｜重要主张的范围与来源依据

对会影响项目判断的关键主张，尽可能保留以下信息中真正重要的部分：

- 说法来自谁，属于亲历、转述、观点还是正式文件/数据；
- 说法对应哪个案例、对象和时间段；
- 是否有原记录中的时间戳、段落号、页码或其他定位；
- 当前证据实际支持的是正式规则、某次事件、发生频率、权限、原因还是结果；
- 证据基础、适用范围和验证状态分别是什么，不能混成一个标签。

注意：

- 制度文件支持制度规定，不自动证明实际执行；
- 单一访谈支持该受访者的陈述或经历，不自动支持组织普遍性；
- 多个说法只有在来源实质独立时才构成交叉佐证；
- “已核实”只在证据与主张类型、范围和时间相匹配时使用；
- 来源是否亲历、实际掌握相关信息、与其他来源是否共享上游信息，必要时作为来源局限记录，不据此推断动机。

这些信息只在影响理解、追问或后续验证时简短展示。多个来源之间存在重要支持、矛盾、流程顺序或来源依赖时，才在内部形成简短关系描述；只有跨角色/跨案例综合会改变后续行动时，才形成有限议题画像。普通纪要仍保持轻量，不展示内部五层标签，不增加固定证据评分表或冗长方法说明，也不建立持久证据图谱。

## 6. Uncertainty and transcript defects

出现以下情况不得自行补全：

- 转写明显缺字或中断；
- 人名、数字、制度名称听写不清；
- 指代对象无法确定；
- 前后说法互相矛盾；
- 记录只保留片段，无法确认完整语境。

使用 `待核实`、`原记录不清`、`无法确认` 等简短标记即可，不需要展开方法说明。

## 7. Compare with current context when useful

如果当前上下文已经存在项目资料或前序访谈，纪要完成后只补充少量真正重要的关系，例如：

- 本次补充了哪些此前未知信息；
- 是否出现影响后续访谈的实质冲突；
- 哪些关键问题需要换一个角色继续确认。

详细的“新增信息 → 后续访谈刷新”按 `references/interview-delta.md` 执行，不要在普通纪要里重复做完整 Delta。

如果此前资料不在当前上下文，不假装能够做历史对比。

## 8. Follow-up suggestions

只有出现明确的信息缺口、冲突或高价值待核实事项时，才增加后续建议，例如：

- 向哪类角色确认；
- 查哪类制度/数据；
- 下一场访谈验证什么。

默认保持简短，不自动扩展成正式诊断、竞争假设清单或大段行动计划。

## 9. Quality check

- 有没有遗漏会改变理解的重要观点、数字或案例；
- 有没有把受访者观点写成客观事实；
- 有没有增加原文不存在的原因、动机或评价；
- 重要限定词是否被压缩掉；
- 原材料已有的重要来源定位是否被无必要丢掉；
- 不确定内容是否明确但简洁地保留；
- 纪要是否像顾问可以直接继续使用的工作成果，而不是证据治理说明书；
- 是否与 `interview-delta.md` 的职责重复；
- 是否越界形成企业级正式诊断。
