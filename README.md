# TalkTrace

TalkTrace 是一个面向管理咨询顾问的轻量调研访谈 Skill。

把项目资料、人员信息或访谈转写交给支持 Skill 的 AI，直接用自然语言说明你下一步要做什么。TalkTrace 会围绕：

> **已经知道什么 → 还缺什么 → 找谁验证 → 这一场问什么 → 新增了什么 → 下一场怎么调整**

帮助你把一次性的“写计划、写提纲、写纪要”，变成连续的信息获取过程。

## 你可以直接做四件事

### 1. 制定访谈计划

根据项目目标、现有资料和信息缺口，判断应该访谈谁、为什么访谈、建议多长时间，以及在约束明确后如何排程。

没有完整时间安排时，TalkTrace 会先给出**访谈对象优先级 + 访谈目的 + 建议时长**，不会为了凑日程编造可用时间。

### 2. 生成访谈提纲

支持两种版本：

- **客户发送版**：正式、简洁，不暴露顾问内部判断；
- **顾问内部版**：结合当前已知信息、未决问题、角色差异和交叉验证需要，方便现场继续追问。

不同角色承担不同的信息任务，不只是替换姓名和职位。

### 3. 整理访谈纪要

把访谈转写或现场记录整理成顾问可直接继续使用的轻量纪要，重点保留：

- 核心观点；
- 关键事实与案例；
- 重要数字、时间、范围和限定词；
- 待核实事项；
- 对后续访谈真正有影响的信息。

如果原始记录已有时间戳、段落号或说话人标签，重要内容会尽量保留可回查定位；输入没有定位时不会虚构。

### 4. 刷新下一场访谈

当当前对话中已经有前期资料/前序访谈，或者宿主能够访问你已授权工作区中的相关既往访谈纪要、访谈汇总、项目资料时，可以直接说：

> “结合已有访谈，更新下一场访谈重点。”

TalkTrace 会先读取当前任务所需的相关现成文件，再识别哪些问题已经回答、出现了什么新信息或冲突、哪些说法仍需第二来源验证，并据此删除低价值重复问题、增加新的验证重点。

如果是在一个全新的会话里，但宿主无法访问相关历史文件，TalkTrace 会明确说明上下文不足，而不是假装记得之前会话。

它既支持“一场新访谈加入后刷新”，也支持“工作区里已经存在多场完成访谈，基于整个语料统一刷新剩余访谈”。你不需要理解 `Delta`、Schema、证据状态或其他内部方法术语。

## 第一次使用，可以直接这样说

上传资料或授权宿主访问已有项目文件后，直接使用普通表达即可，例如：

- `这是客户资料，帮我准备一下访谈。`
- `根据这些资料帮我制定访谈计划。`
- `我要访谈人力资源部长，帮我准备一份45分钟顾问内部版提纲。`
- `把这份访谈转写整理成专业纪要。`
- `工作区里已经有前几场访谈纪要，帮我更新下一场运营负责人的访谈重点。`

如果输入不足，TalkTrace 会尽量先给有用初稿，只追问那些会实质改变结果的信息，不要求你先填一套项目表单。

## 最少需要提供什么

不同任务需要的信息不同，不要求一次准备齐全：

| 任务 | 最有帮助的输入 |
|---|---|
| 访谈计划 | 项目目标、组织/人员资料、已知时间或分组约束 |
| 访谈提纲 | 受访者职务/角色、项目目标、已有项目资料或前序访谈 |
| 访谈纪要 | 可读取的访谈转写、现场记录或二者组合 |
| 下一场刷新 | 当前对话或已授权工作区中可访问的前期资料/前序访谈 + 剩余受访者（如已确定）；可以是一场刚新增访谈，也可以是多场既有语料 |

缺少某项信息时，TalkTrace 不会自动补造组织事实、职责、真实权力关系、流程步骤或人员可用时间。

## TalkTrace 与普通“让 AI 写一份提纲”有什么不同

TalkTrace 的核心不是固定模板，而是四条工作纪律：

- **信息缺口驱动**：先判断项目还缺什么，再决定访谈谁；
- **角色差异**：高层、职能负责人、业务负责人和一线人员承担不同的信息任务；
- **中性求证**：没有证据支持的流程、动作、角色或因果，不作为既定前提塞进问题；
- **来源纪律**：受访者的陈述首先是来源信息，不自动升级成已经验证的企业事实。

TalkTrace 可以识别问题线索、冲突、候选假设和待验证事项，但不会因为一次或少量访谈就直接输出企业级正式管理诊断。

## 安装与运行

### 推荐方式：使用干净的 TalkTrace 运行包

同事安装时，推荐使用已经打包好的 **TalkTrace runtime package**，不要把整个 GitHub 开发仓库当作安装对象。

1. 获取 `TalkTrace-v0.1.0-runtime-<commit SHA>` 运行包 ZIP；
2. 解压后应得到一个 `TalkTrace/` 文件夹；
3. 在支持文件夹型 Skill / 自定义 Skill 的宿主环境中导入这个 `TalkTrace/` 文件夹；
4. 上传项目资料或授权宿主访问已有项目文件，并直接用自然语言提出任务。

运行包由 GitHub Actions 从公开源码自动生成；正式发布后优先使用与当前版本对应的运行包。维护者也可以直接把生成后的 ZIP 发给同事，使用者不需要理解仓库中的测试、CI 或适配文件。

运行包只包含：

```text
TalkTrace/
├── SKILL.md
├── references/
│   ├── interview-plan.md
│   ├── interview-guide.md
│   ├── interview-notes.md
│   └── interview-delta.md
└── assets/
    ├── interview-plan-template.csv
    ├── interview-guide-client.md
    ├── interview-guide-internal.md
    └── interview-notes-template.md
```

仓库中的 `README.md`、`evals/`、`.github/`、`docs/`、`workbuddy/`、`packaging/` 属于维护、测试、打包或运行环境适配资料，不进入同事安装的运行包。

分发包文件清单由 `packaging/runtime-files.txt` 统一定义，CI 会按该清单自动组装并校验，避免手工维护第二套 Skill 文件。

具体“导入 Skill”的入口由宿主平台决定；TalkTrace 不要求额外第三方 API、账号凭证、独立网络回调或遥测。

## 运行环境能力

TalkTrace 本身保持零私有依赖，但实际能读取什么文件、能否生成可下载 Excel/Word、能否转写音频，取决于宿主运行环境。

- Word / PPT / PDF / Excel 等文件：宿主能原生读取时直接使用；
- 已授权工作区历史文件：宿主能够列出并读取时，TalkTrace 可以在新会话中按当前任务需要重新读取相关现成文件，重建本次上下文；这不是跨会话持久记忆；
- Excel/Word artifact：宿主支持文件生成时可以交付真实文件；不支持时应如实说明，不能把 Markdown 表格冒充为 Excel；
- 音频：宿主能可靠转写时可使用转写结果；否则请提供可读转写文本；
- 长项目历史：TalkTrace v0.1.0 不创建或维护持久 Project Memory；如果宿主不能访问历史文件，就无法可靠恢复历史上下文，必须明确降级。

## v0.1.0 明确不做

- 持久 Project Memory / 项目数据库；
- RAG / 向量数据库；
- 自主 Agent；
- MCP / 私有 Connector 依赖；
- 用户私有知识库或其他私有 Skill 依赖；
- 专用文件转换 / 知识化平台；
- 内置第三方转写服务；
- 自动邮件 / 日历邀请；
- 情绪、人格或可信度评分；
- 自动生成正式管理诊断、完整咨询报告或 PPT。

## 数据与隐私

- 公开仓库不提交真实客户资料、访谈、姓名、敏感数字或专有制度文本；
- 示例与测试材料必须使用合成或公开安全数据；
- TalkTrace 本体不引入额外第三方 API、独立网络回调、账号凭证或遥测；
- 实际模型调用、文件处理和数据传输仍由宿主运行环境决定，应遵循该平台的数据与权限政策。
