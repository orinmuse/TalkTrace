# TalkTrace

TalkTrace 是一个面向咨询顾问的轻量调研访谈 Skill。

它不是简单生成“访谈计划 / 访谈提纲 / 访谈纪要”三个静态文档，而是使用**当前 AI 工作上下文**中的项目资料和访谈记录，围绕：

> **已经知道什么 → 还缺什么 → 找谁验证 → 这一场问什么 → 新增了什么 → 下一场怎么调整**

持续辅助调研访谈。

## 核心工作流

```text
项目资料
→ 初步项目理解
→ 已知信息 / 未决问题
→ 访谈对象与信息任务
→ 访谈计划
→ 差异化访谈提纲
→ 访谈纪要
→ 新增信息 / 冲突 / 待验证事项
→ 刷新后续访谈
```

TalkTrace 的目标不是替代顾问判断，而是减少重复阅读、基础整理和项目上下文记忆负担，让后续访谈随着信息增加而逐步变得更有针对性。

## 使用方式

把当前项目资料或访谈记录提供给支持 Skill 的 AI 运行环境，然后直接用自然语言提出任务，例如：

- `根据这些项目资料帮我制定访谈计划。`
- `给人力资源负责人准备一份顾问内部访谈提纲。`
- `把这份访谈转写整理成专业纪要。`
- `结合前面的项目资料和刚才这场访谈，告诉我新增了什么、还有什么要验证，并更新下一场访谈提纲。`

正常用户不需要理解或维护任何内部 Workflow、Schema、数据库或项目状态文件。

## 当前上下文就是工作记忆

TalkTrace v0.1 不建立持久项目数据库，也不要求额外状态文件。

- 当前上下文中已有的项目资料、前序访谈和用户补充信息，可以继续使用；
- 不在当前上下文中的信息，不假装记得；
- 文件理解依赖宿主大模型的原生能力；必要时可临时整理为 Markdown，但 TalkTrace 不建设专用文档转换平台。

## v0.1 主要能力

### 1. 项目资料理解

区分：

- 材料已经明确的信息；
- 可以形成但仍应保持可修正的初步工作理解；
- 仍需通过访谈验证的事项。

### 2. 信息缺口驱动的访谈计划

不是从“有哪些领导和部门”开始，而是：

`项目问题 → 信息缺口 → 最合适的信息来源 / 交叉验证对象 → 访谈优先级和时长 → 排程`

用户需要时，可在支持的运行环境中生成真实可编辑 Excel 访谈计划。

### 3. 两套访谈提纲

- **客户发送版**：正式、简洁、不暴露内部判断；
- **顾问内部版**：可包含当前已知信息、未决/冲突、提问目的、可选追问和后续交叉验证。

所有问题必须遵守 premise-safety：未经证据支持的主体、动作和机制不能作为既定前提塞进问题。

### 4. 结构化访谈纪要

保留：

- 受访者原意；
- 重要数字、时间、限定词和案例；
- 事实性陈述与已验证事实之间的边界；
- 输入中已有的时间戳、段落号、说话人等必要来源定位。

### 5. 访谈信息递进更新

如果当前上下文同时存在前期资料 / 前序访谈和一场新访谈，TalkTrace 会识别：

- 本次新增信息；
- 哪些开放问题得到回答；
- 与既有信息的冲突；
- 只有单一来源支持、需要继续验证的重要说法；
- 新暴露的问题；
- 最合适的下一验证对象；
- 后续提纲需要删除、新增或调整的内容。

## 设计原则

- **信息需求优先**：先判断缺什么信息，再决定访谈谁；
- **项目资料优先**：项目事实优先于通用行业知识；
- **角色差异**：不同角色承担不同的信息任务；
- **中性求证**：先确认实际发生了什么，再追问谁、为什么、如何；
- **来源纪律**：受访者陈述首先是来源，不自动等于企业事实；
- **上下文递进**：前面访谈已经回答的内容，不应在后续机械重复；
- **最少追问**：只询问会实质改变当前成果的信息；
- **复杂度内收**：普通用户只需提供材料并提出自然语言任务。

## 明确不做

TalkTrace v0.1 不包含：

- 持久项目状态文件 / 项目数据库；
- RAG / 向量数据库；
- 自主 Agent；
- 跨访谈证据图谱；
- 专用文件转换 / 知识化平台；
- 用户私有知识库或私有 Capability 依赖；
- 内置录音 / 第三方转写服务；
- 自动邮件 / 日历邀请；
- 企业知识管理；
- 情绪、人格或可信度评分；
- 自动生成正式管理诊断、完整咨询报告或 PPT。

TalkTrace 可以识别问题线索、冲突、候选假设和待验证事项，但停止在正式企业级管理诊断之前。

## 数据与隐私

本仓库按未来公开发布标准管理：

- 不提交真实客户资料、访谈、姓名、敏感数字或专有制度文本；
- 示例与测试材料必须为合成或公开安全数据；
- TalkTrace 本体不要求额外第三方 API、账号凭证、独立网络回调或遥测；
- 实际模型调用、文件处理和数据传输由宿主运行环境决定，应遵循该平台的数据与权限政策。
