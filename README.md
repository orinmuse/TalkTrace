# TalkTrace

TalkTrace 是一个面向管理咨询顾问的调研访谈 Skill。

默认按照咨询顾问的真实工作节奏运行：先预检收到的资料，白天由顾问独立访谈，每天结束集中上传一批纪要，随后修正调研认识与次日行动。它把一次性的“写计划、写提纲、写纪要”，变成一条连续的信息获取工作流：

> **进场前资料预检 → 分角色访谈 → 日终批次回传 → 修正已有认识 → 次日问谁、查什么 → 阶段性收口**

适合管理体系现状摸底、组织与职能调研、战略访谈、具体业务实践核验等需要连续访谈和交叉验证的咨询场景。TalkTrace 根据调查目标和对象选择方法：管理体系现状调查先建立项目范围内的主题地图；具体业务实践再按需开展案例与流程穿透。

## 顾问每天怎样使用

- **D0 进场前**：授权/上传现有资料，生成当前重要问题、访谈计划和首日提纲。
- **D1/Dn 白天**：顾问独立访谈；没有实时上传、额外表单或同时访谈多个部门的要求。
- **每天结束后**：按平常方式整理并上传当天纪要（一个部门也可以），AI 读取本次确实可访问的前序资料，修正已有认识、指出重要冲突并输出次日角色/资料核验行动。
- **跨会话**：必须重新读取有授权的历史原始资料才可可靠比较跨日变化；仅有当天材料时须明确降级。用户可按需取得一份普通交接快照，但它不是独立事实来源。

## 调查方法如何选择

- **管理体系现状摸底**（如薪酬绩效、组织、岗位职级）：先根据项目范围建立轻量主题地图，分别了解正式设计、实际运行、相关主体的理解与体验，再针对重要差异深入。
- **专项业务实践核验**：针对具体流程、事件或能力运行，按需还原真实案例、工作过程和组织条件；适用时使用“源—点—线—面—果—环”。
- **特定争议澄清**：围绕明确主张，选择中性问题和匹配的记录/角色进行核实。

“源—点—线—面—果—环”仍然是对客户真实业务实践的调查：业务起点、具体实践、工作责任链、重复与复制、实际结果、客户组织自身的反馈调整与再运行。它不是管理体系现状摸底的默认框架，也不是“文件来源—观点—关系—覆盖—AI 下一问”的证据分类表。主题覆盖状态与主张证据状态分开管理。

## TalkTrace 可以直接做什么

### 1. 制定访谈计划

根据项目目标、调查对象、已有资料和主题覆盖，先判断本轮要摸清哪些现状主题，再决定：

- 应该访谈谁；
- 为什么访谈这个人；
- 建议多长时间；
- 本场重点验证什么；
- 在排程条件明确后，如何形成正式访谈日程。

如果日期、分组、人员可用时间等信息还不完整，TalkTrace 会先给出可执行的快速计划，不会为了凑完整日程编造人员时间。

### 2. 生成差异化访谈提纲

TalkTrace 会根据受访角色真正掌握的信息来设计问题，而不是给不同人套用同一套模板。内部提纲还会根据回答内容选择下一步追问：必要时还原具体案例、步骤、参与者、依据、例外和影响，而不是把预设问题全部问完。

支持两种常用版本：

- **客户发送版**：简洁、正式，可提前发给受访者，不暴露顾问内部判断；
- **顾问内部版**：结合已有资料、前序访谈、待验证事项和必要追问，方便现场使用。

高层、职能负责人、业务负责人和一线人员承担不同的信息任务，因此提问重点也会不同。

### 3. 整理专业访谈纪要

把访谈转写、现场记录或二者组合交给 TalkTrace，可以整理为顾问可直接继续使用的轻量纪要，重点保留：

- 核心观点；
- 关键事实与案例；
- 重要数字、时间、范围和限定词；
- 待核实事项；
- 对后续访谈真正有影响的信息。

TalkTrace 会保留来源边界：某位受访者的说法首先是“这个人这样说”，不会因为被整理进纪要就自动升级成已经验证的企业事实。

### 4. 刷新下一场访谈

当已有前序访谈后，可以直接说：

> “结合已有访谈，更新下一场访谈重点。”

TalkTrace 会重新判断：

- 哪些问题已经回答，可以不再重复问；
- 哪些说法存在冲突；
- 哪些内容仍是单一来源，需要第二来源验证；
- 新出现了哪些信息缺口；
- 下一位受访者最值得验证什么。

它既支持“一场新访谈加入后的刷新”，也支持“工作区已经有多场访谈，基于整个语料统一刷新剩余访谈”。

如果是在一个全新的会话中，只要宿主能够访问你已经授权的项目资料、历史访谈纪要或访谈汇总，TalkTrace 会先读取这些现成文件，再重建本次任务需要的上下文。

如果宿主无法访问历史资料，TalkTrace 会明确说明上下文不足，而不是假装记得之前的会话。

## 第一次使用

不需要学习专门指令。把当前项目资料交给支持 Skill 的 AI 后，直接用普通语言提出任务即可，例如：

- `这是客户资料，帮我准备一下访谈。`
- `根据这些资料帮我制定访谈计划。`
- `我要访谈人力资源负责人，帮我准备一份45分钟顾问内部版提纲。`
- `把这份访谈转写整理成专业纪要。`
- `工作区里已经有前几场访谈纪要，帮我更新下一场运营负责人的访谈重点。`

如果输入不足，TalkTrace 会尽量先给出有用初稿，只追问那些会实质改变结果的信息，不要求先填写完整项目表单。

## TalkTrace 与普通“让 AI 写一份提纲”有什么不同

TalkTrace 的核心不是固定模板，而是七条工作纪律：

- **目标与主题驱动**：先识别调查对象和范围；体系摸底先形成项目化主题地图，具体实践再选择案例穿透；
- **信息缺口驱动**：先判断项目还缺什么，再决定访谈谁；
- **角色差异**：不同角色承担不同的信息任务；
- **中性求证**：没有证据支持的流程、职责、因果或机制，不作为既定事实塞进问题；
- **来源纪律**：访谈陈述首先保留为来源信息，不自动升级为企业事实；多名受访者的信息是否独立也需要判断。
- **回答驱动追问**：根据实际回答选择最有价值的下一问，不机械执行固定题库。
- **证据适配**：制度、案例、数据和访谈分别支持不同类型的主张，不把一种证据越级用于证明另一种判断。
- **关系与范围纪律**：把原始来源、具体信息、信息关系和覆盖边界区分开；不把零散说法简单汇总成组织事实。

因此，TalkTrace 的价值不只是“写得更快”，而是帮助后续访谈真正吸收前序信息，减少重复提问，并持续提高验证效率。

## 安装

TalkTrace 的源码与版本治理记录以本仓库为准。正式分发版与候选分发包应区分；实际导入 Skill 时，推荐使用干净的 TalkTrace 运行目录或对应版本的分发 ZIP，而不是把整个开发仓库作为 Skill 运行目录。

标准运行目录应为：

```text
TalkTrace/
├── SKILL.md
├── references/
│   ├── interview-plan.md
│   ├── interview-guide.md
│   ├── interview-notes.md
│   ├── interview-delta.md
│   └── company-interview-guide.md
└── assets/
    ├── interview-plan-template.csv
    ├── interview-guide-client.md
    ├── interview-guide-internal.md
    ├── interview-notes-template.md
    └── interview-guide-company-client.md
```

运行目录共11个文件。安装时保留完整目录，不混用不同版本文件；运行包不包含客户原件、评测输出或仓库维护文件。

ZIP 分发包按版本命名：

- `TalkTrace-v0.1.1-WorkBuddy.zip`：当前正式分发基线；
- `TalkTrace-v0.2.0-candidate-WorkBuddy.zip`：内部受控试用候选；WorkBuddy S10 目标运行时及真实项目多日效果尚未验证；
- `TalkTrace-v0.3.0-candidate-WorkBuddy.zip`：CR-05 方法重构候选，已完成候选封装，仅供内部受控试用；WorkBuddy S11 目标运行时及真实项目现场效果尚未验证。

v0.2.0-candidate 与 v0.3.0-candidate 均不替代 v0.1.1 正式分发基线。
在支持文件夹型 Skill / 自定义 Skill 的宿主环境中导入其中的 `TalkTrace/` 文件夹即可。

GitHub 仓库同时包含测试、CI、分享材料和维护文件，因此**不要把整个仓库目录直接当成 Skill 运行目录**。

不同 AI 平台的 Skill 导入入口可能不同，以实际宿主能力为准。

## 运行环境说明

TalkTrace 本身不要求额外第三方 API、账号凭证、数据库或网络回调，但实际可以读取什么文件、生成什么文件，取决于宿主环境。

- **Word / Excel / PPT / PDF**：宿主能原生读取时直接使用；
- **已有项目历史文件**：宿主能访问时，TalkTrace 可以在新会话中重新读取并恢复本次任务所需上下文；
- **Excel / Word 成果**：宿主支持真实文件生成时可以直接交付；不支持时会如实说明；
- **音频**：宿主能够可靠转写时可使用转写结果，否则请提供可读文本；
- **长项目历史**：如果宿主无法访问历史文件，TalkTrace 无法可靠恢复过去的项目上下文。

## 能力边界

TalkTrace 当前正式分发基线 v0.1.1 及 v0.2.0 / v0.3.0 候选版均聚焦调研访谈工作流，不负责：

- 建立持久项目数据库或跨会话长期记忆；
- RAG / 向量数据库；
- 自主 Agent；
- MCP 或私有 Connector 依赖；
- 用户私有知识库或其他私有 Skill 依赖；
- 专用文件转换平台；
- 内置第三方转写服务；
- 自动邮件或日历邀请；
- 情绪、人格或可信度评分；
- 根据一次或少量访谈直接生成正式企业诊断、完整咨询报告或 PPT。

TalkTrace 可以帮助识别问题线索、冲突、候选假设和待验证事项，但正式诊断仍需要结合更完整的制度、数据、访谈和顾问判断。

## 数据与隐私

- 仓库中的示例和测试材料使用合成或公开安全数据；
- TalkTrace 本体不引入额外第三方 API、独立网络回调、账号凭证或遥测；
- 实际模型调用、文件处理和数据传输由宿主运行环境负责，应遵循相应平台的数据与权限政策。
